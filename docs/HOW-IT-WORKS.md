# Как устроен HapasVault

Технические подробности для тех, кто хочет проверить, а не верить на слово.
Коротко для пользователей — в [README](../README.md), модель угроз и аудит —
в [SECURITY.md](../SECURITY.md).

## Ключи

```
seed     = BLAKE2b(rand_token || rand_pc)            -> 24 слова BIP39
K_token  = KDF(seed, "k_token")                       хранится на токене
K_pc     = KDF(seed, "k_pc")                          хранится на ПК (DPAPI)
pw_hash  = Argon2id(мастер-пароль, соль из K_pc)      64 МиБ, 3 прохода, на ПК
K_vault  = KDF(K_token, K_pc || pw_hash)              только в RAM токена
```

* Seed складывается из случайности обеих сторон: слабый RNG RP2040 не страшен,
  и ПК не может подсунуть заранее известный seed.
* Seed не сохраняется нигде, кроме бумаги пользователя.
* Расшифровка идёт **на токене**; ПК получает только одну запрошенную запись.
  Команды «выгрузить всё» нет, резервная копия — только шифротекст.
* Мастер-пароль входит в ключ хранилища, поэтому без него не открыть ни
  токен, ни резервную копию.

## Канал ПК ↔ токен

* Первый ПК: обмен статическими ключами X25519 с чистым токеном (trust on first
  use). Остальные компьютеры — до 4 на токен — привязываются **по 24 словам**:
  ПК выводит из фразы K_token и подписывает им свой ключ, токен проверяет
  подпись (после неверной — пауза 1 с). Без фразы новый ПК не привязать.
  Подпись: `BLAKE2b(key = K_token, "pmtoken pair v2" ‖ ключ ПК ‖ ключ токена ‖ эпоха)`,
  где эпоха привязки хранится во flash токена и растёт при каждой отвязке ПК.
  Отвязанный ПК получает отказ уже на рукопожатии, а повтор его старого кадра
  привязки не проходит: вернуть ПК можно только снова по 24 словам.
* ПК знает до 4 токенов (основной, запасной…) и сам узнаёт подключённый по его
  публичному ключу (открытый кадр WHO: ключ токена, настроен ли, сколько ПК
  привязано, эпоха привязки).
* Каждая сессия: рукопожатие по схеме Noise KK (эфемерные ключи, четыре DH) —
  forward secrecy и взаимная аутентификация. Чужой ПК получает отказ на первом
  же кадре.
* Кадры: XChaCha20-Poly1305 со счётчиком. Повтор, перестановка или подмена
  рвут сессию.
* Транспорт — USB CDC (виртуальный COM-порт), драйвер не нужен. Отключение USB
  или закрытие порта = блокировка: ключи стираются из RAM токена.

## Что лежит на flash токена

| Данные | Вид |
|---|---|
| статический ключ X25519 токена, K_token, публичные ключи и имена привязанных ПК | открыто (без K_pc и пароля бесполезны) |
| записи (категории, названия, логины, пароли, секреты 2FA и Steam) | XChaCha20-Poly1305, ключ K_vault |

Тест проверяет, что в дампе flash нет ни паролей, ни названий, ни K_pc.

## Встроенные политики (`core/token.h`)

| Политика | Значение |
|---|---|
| таймаут простоя | 5 мин без кадров сессии → блокировка и закрытие сессии (открытые кадры WHO его не продлевают) |
| отключение USB | немедленная блокировка, ключи стираются из RAM |
| лимит расшифровок | 10 в минуту |
| неверный пароль | 3 попытки без задержки, затем 1, 2, 4 … с, не больше часа; счётчик во flash (после 3 ошибок — пишется до проверки пароля) |
| имя ПК | не больше 4 смен в минуту (запись во flash) |
| коды 2FA | 30 в минуту; пока токен включён, время ПК не может обогнать его часы больше чем на 5 мин; назад дальше сохранённой во flash отметки — нельзя |
| подтверждения Steam | 30 ключей в минуту, только на текущее время, одобрения — в журнал |
| журнал | последние 32 операции (в RAM, до перезагрузки), только при открытом хранилище |
| ёмкость | вся свободная RAM платы (RP2040 ~195 КБ, RP2350 ~450 КБ), определяется сама |

## Двухфакторные коды и Steam

Секрет TOTP или Steam Guard уходит на токен один раз и больше никогда не
выдаётся: программа присылает токену текущее время, токен возвращает только
код. Пока токен включён, время не может обогнать его часы больше чем на
5 минут, поэтому набрать коды «на будущее» в течение работы нельзя. Часов на
батарейке у токена нет: первый запрос после включения может назвать любое
будущее время (подробнее — в [SECURITY.md](../SECURITY.md)). Назад, раньше
сохранённой во flash отметки, время не уходит.

Для подтверждений Steam (обмены, торговая площадка, ключ API):

| | Токен | ПК |
|---|---|---|
| `identity_secret`, `shared_secret` | хранит, наружу не выдаёт | — |
| ключ каждого запроса | HMAC-SHA1(identity_secret, время ‖ тег) | присылает время и тег |
| код Steam Guard для входа | считает | — |
| пароль аккаунта | хранит (как любую запись) | получает на время входа |
| код восстановления | хранит, выдаёт по запросу с лимитом и в журнал | показывает 30 с |
| сессия Steam (refresh token) | — | DPAPI, `%APPDATA%\HapasVault\steam` |
| сеть (steamcommunity.com, api.steampowered.com) | — | делает запросы |

Вход в Steam устроен как в мобильном Modern-SDA: вход как браузер,
`jwt/finalizelogin` выдаёт cookie сообщества, время сверяется с серверами
Steam, `device_id` берётся из maFile. Сессия из maFile нового формата
(`RefreshToken`) подхватывается без входа. Сессия на ПК сама по себе ничего
не подтверждает — без токена ключ подтверждения не получить.

## Память и разметка flash

Всё открытое хранилище при работе лежит в RAM платы (расшифровка только там),
поэтому ёмкость задаёт RAM, а не flash. Прошивке нужно ~38 КБ, всю остальную
свободную RAM она отдаёт под хранилище: **RP2040 — около 195 КБ, RP2350 — около
450 КБ** (1–3 тыс. обычных записей). Flash нужно вдвое больше (две копии), что
с запасом есть на любой плате. Буфер кадра — 8 КБ: резервная копия и список
записей передаются частями.

```
0 … 256 КБ                прошивка (сейчас ~80 КБ, остальное — запас на рост)
…                          свободно
конец − 8 КБ − 2S         хранилище, слот A
конец − 8 КБ − S          хранилище, слот B
конец − 8 КБ              конфигурация A и B
```

Разметка привязана к концу flash, размер слота S выбирается при первой
настройке по RAM платы и записывается в конфигурацию — обновление прошивки её
не сдвигает. Запись всегда идёт в слот со старой копией, у каждой копии есть
счётчик и контрольная сумма: выдёргивание во время записи откатывает к
предыдущей версии (есть тест). Платы с прежней разметкой (всё в последних
80 КБ) переносятся автоматически при первом запуске новой прошивки.

## Скорость

На Pico (RP2040, 125 МГц), по счётчику тактов в эмуляторе: установка сессии
~0,4 с (четыре X25519 на Cortex-M0+), остальные команды 5–60 мс, плюс ~0,4 с на
стирание flash у команд, меняющих хранилище. RP2350 (Cortex-M33, 150 МГц)
быстрее в несколько раз.

## USB-идентификатор

Сейчас `1209:0001` — общий тестовый PID pid.codes, им пользуются и другие
самодельные устройства. Поэтому программа подключается только к устройству,
которое называет себя `pmtoken` (строка продукта и интерфейса USB): чужая плата
с тем же ID не будет принята за токен. Свой PID бесплатно дают
[pid.codes](https://pid.codes) (открытым проектам; GPL-3.0 подходит) и
Raspberry Pi для устройств на своих чипах (VID `2E8A`, репозиторий
`raspberrypi/usb-pid`). Новые значения — в `core/proto.h`: `PM_USB_VID`,
`PM_USB_PID`, `PM_USB_PRODUCT`.

## Интерфейс

* Логин и пароль запрашиваются у токена только по действию пользователя и
  стираются из памяти интерфейса через 30 секунд.
* Скопированный пароль не попадает в журнал буфера Win+V и облачный буфер,
  буфер очищается через 30 секунд.
* Автоблокировка при бездействии, при блокировке Windows и перед сном.
* Пока хранилище открыто, программа не опрашивает токен — иначе токен не смог
  бы закрыться по простою.
* Ключ ПК (`%APPDATA%\HapasVault\pmclient.id`) защищён DPAPI.
* Автоввод — события клавиатуры Unicode (раскладка не важна). В окна,
  запущенные от администратора, Windows вводить не даёт — тогда значение
  копируется в буфер обмена.
